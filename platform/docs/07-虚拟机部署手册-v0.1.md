# 07 中心端虚拟机部署手册 v0.1

目标：在本机用 VirtualBox 起一台 Ubuntu Server，把整套平台（web / backend / mysql）搬进去，让同事能通过局域网 IP 访问，扩展把数据推到这台服务器上。

适用：Windows 宿主机 + VirtualBox 7.x + Ubuntu Server 24.04 LTS。
本文命令为主，路径和密码按你机器实际情况替换，其余可直接粘。

---

## 0. 开工前先认三件事

| 事项 | 结论 | 影响 |
| --- | --- | --- |
| 虚拟机跑在你这台电脑上 | 宿主关机 / 休眠 / 断网，同事立刻断 | 想 7×24 就得迁到一台常开的机器，步骤完全一样 |
| 必须固定 IP | DHCP 换 IP 后，扩展、同事的书签全废 | 第 4 步写死静态 IP |
| 同一台电脑只能指一个平台 | WSL 版和虚拟机版同时在跑，扩展往哪边推就成谜 | 迁完后停掉 WSL 版（第 12 步） |

资源基线：**内存 4096 MB、CPU 2 核、磁盘 40 GB**（MySQL 约 1 GB，backend 约 1 GB，余量给系统）。宿主机至少留 8 GB 空闲。

---

## 1. 建虚拟机（VirtualBox 图形界面）

VirtualBox → 新建，按下表填：

| 项 | 值 |
| --- | --- |
| 名称 | `dya-platform` |
| 类型 / 版本 | Linux / Ubuntu (64-bit) |
| 内存 | `4096 MB` |
| 处理器 | `2` |
| 硬盘 | `40 GB`，VDI，**动态分配** |

建完点「设置」：

- **网络 → 网卡 1**：连接方式选 **桥接网卡（Bridged Adapter）**，界面名称选你实际上网那块网卡。
  - 有线就选 `Realtek/Intel ... Ethernet`
  - Wi-Fi 就选 `... Wi-Fi / Wireless`
  - 选错的表现：装完系统没有 IP、上不了网、Windows ping 不通。
- **系统 → 处理器**：勾「启用嵌套分页」；**显示 → 显存** 16 MB 即可（无桌面环境，不需要 3D）。

「存储」里挂 Ubuntu Server 24.04 ISO（`ubuntu-24.04.x-live-server-amd64.iso`）。

> 不想桥接（公司网络限制 MAC / 无 DHCP）也可以改 **NAT + 端口转发**：高级 → 端口转发 → 加一条 `主机 19203 → 子系统 19203`，再加速 SSH `主机 2222 → 子系统 22`。代价是只有本机能访问，同事进不来，不推荐。

## 2. 装 Ubuntu Server

启动虚拟机，按提示走。只有几处要改，其余默认：

| 步骤 | 选择 |
| --- | --- |
| 语言 | **English**（选中文时 TTY 会出方块，日志也难搜） |
| 键盘 | 默认 |
| 安装类型 | `Ubuntu Server`（不选 minimized，省得后面缺 curl） |
| 网络 | 先让它 DHCP 拿到地址，能联网就行 |
| 代理 | 留空 |
| 镜像源 | 默认（慢的话换 `https://mirrors.aliyun.com/ubuntu/`） |
| 磁盘 | 整盘，默认 LVM，不加密 |
| 用户 | 用户名建议 `dya`，密码自己记牢 |
| **SSH** | **勾选 `Install OpenSSH server`**（必勾，否则后面 scp 用不了） |
| 附加软件 | 全不选（不需要 docker snap、不需要 k8s） |

装完重启，登录后记下 IP：

```bash
ip -4 addr show | grep inet
```

在 Windows 上验证 SSH 通：

```powershell
ssh dya@<虚拟机IP>
```

> Windows 自带 OpenSSH 客户端；没有就「设置 → 应用 → 可选功能」里装 `OpenSSH Client`。

## 4. 固定 IP（netplan）

先确认网卡名和网关：

```bash
ip route | grep default      # 记下 dev 名（如 enp0s3）和 via 后面的网关
```

假设：网卡 `enp0s3`、要用的 IP `192.168.1.50`、网关 `192.168.1.1`、DNS `223.5.5.5`。

> **IP 怎么选**：在你 Windows 上 `ipconfig` 看「默认网关」和本机 IP，选同网段里一个没人用的（例如本机是 192.168.1.23，就挑 192.168.1.50）。**不要和本机 IP 相同**。

```bash
sudo tee /etc/netplan/99-static.yaml >/dev/null <<'EOF'
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [192.168.1.50/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [223.5.5.5, 119.29.29.29]
EOF
sudo chmod 600 /etc/netplan/99-static.yaml
sudo netplan apply
```

验证：

```bash
ip -4 addr show enp0s3 | grep inet    # 出现 192.168.1.50
ping -c 3 223.5.5.5                   # 外网通
```

回到 Windows：

```powershell
ping 192.168.1.50
ssh dya@192.168.1.50
```

两条都通，网络这块就结束了。

## 5. 装 Docker

Ubuntu 24.04 自带的 `docker.io` + `docker-compose-v2` 足够，比 `get.docker.com` 稳：

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

**退出 SSH 重登一次**（让 docker 组生效），然后验证：

```bash
docker version --format '{{.Server.Version}}'
docker compose version
```

期望：Docker `24.x` 以上、Compose `v2.x`。

> 如果 `docker compose` 提示 command not found，说明装的是 `docker-compose`（v1），改用 `sudo apt install -y docker-compose-v2` 重来。

可选：给 Docker 配国内镜像加速（拉 mysql 慢时用）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io"] }
EOF
sudo systemctl restart docker
```

## 8. 写 `.env`

```bash
cd ~/dya/platform/deploy
cp .env .env.bak 2>/dev/null || true
openssl rand -base64 48 | tr -d '\n'      # 记下这串，填到 JWT_SECRET
```

```bash
cat > .env <<'EOF'
MYSQL_ROOT_PASSWORD=换成你的root密码
DB_NAME=collect_platform
DB_USER=collect
DB_PASSWORD=换成你的业务密码
JWT_SECRET=上面openssl生成的那串
BOOTSTRAP_CODE=INTERN01
BOOTSTRAP_NAME=Admin
BOOTSTRAP_PASSWORD=admin123
WEB_PORT=19203
EOF
chmod 600 .env
```

变量说明：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | 是 | MySQL root 密码，不填 compose 直接报错 |
| `DB_PASSWORD` | 是 | 业务账号 `collect` 的密码 |
| `JWT_SECRET` | 是 | 登录令牌签名，换了所有人重新登录；不要和 WSL 那套相同 |
| `DB_NAME` / `DB_USER` | 否 | 默认 `collect_platform` / `collect` |
| `WEB_PORT` | 否 | 对外端口，默认 `19203` |
| `BOOTSTRAP_CODE` / `BOOTSTRAP_NAME` / `BOOTSTRAP_PASSWORD` | 否 | 首次启动创建的管理员，默认 `INTERN01` |

> 想换端口（比如 19203 被占）只改 `WEB_PORT`，扩展和同事的地址跟着改。

## 10. 迁移 WSL 里的现有数据（保留历史）

### 10.1 在 Windows 上导出

先用 root 密码直连（下面的密码换成你 WSL 版 `deploy/.env` 里的 `MYSQL_ROOT_PASSWORD`，默认 `collect_root_2026`）：

```powershell
wsl -d Ubuntu-24.04 -- bash -c "docker exec deploy-mysql-1 mysqldump -uroot -pcollect_root_2026 --single-transaction --quick --routines --triggers --set-gtid-purged=OFF --databases collect_platform > /mnt/c/Users/dataeye/Desktop/collect_platform.sql"
```

导出文件约几十 MB，检查一眼：

```powershell
(Get-Item "$env:USERPROFILE\Desktop\collect_platform.sql").Length / 1MB
```

太小（< 1 MB）说明导空了，先确认 WSL 容器名 `deploy-mysql-1` 是 `Up`。

### 10.2 传到虚拟机

```powershell
scp "$env:USERPROFILE\Desktop\collect_platform.sql" dya@192.168.1.50:~/
```

### 10.3 在虚拟机里导入

先只起数据库，等 healthy：

```bash
cd ~/dya/platform/deploy
docker compose up -d mysql
docker compose ps mysql          # 等 STATUS 出现 (healthy)
```

导入（密码换成新 `.env` 里的 `MYSQL_ROOT_PASSWORD`）：

```bash
docker compose exec -T mysql mysql -uroot -p新root密码 < ~/collect_platform.sql
```

校验行数：

```bash
docker compose exec -T mysql mysql -uroot -p新root密码 -e \
 "select count(*) as videos from collect_platform.videos; select count(*) as authors from collect_platform.authors; select count(*) as uploads from collect_platform.video_uploads;"
```

记下这三个数，WSL 那边跑同样的语句对比，一致就迁移完成。

> 备份里带了 `flyway_schema_history`，所以已执行过的迁移不会重跑；后端升级后新增的迁移（如 V5）会在下次启动时自动补上。

### 10.4 起全量服务

```bash
docker compose up -d
docker compose ps
```

打开页面看「今日总览」数字是否和 WSL 版一致。

## 11. 扩展改地址

中心端 IP 变了，扩展必须跟着改，否则还在往 `127.0.0.1` 推。

1. Chrome 打开 `chrome://extensions` → 「抖音AI合集作者采集」→ 点 **扩展图标** 打开弹窗
2. 勾选「同步到采集平台」
3. 「平台地址」填 `http://192.168.1.50:19203`（**不要带结尾斜杠**）
4. 「采集密钥」填 `dya-collect-2026`
5. 回到 `chrome://extensions`，点卡片上的 **刷新图标** 重载扩展
6. 回到抖音标签页按 **F5**

验证：平台 →「实时采集区 → 采集工作区」，下拉里出现 `dev-xxxxxxxx` 且显示「在线」；「今日总览」的入库数字开始涨。

> 扩展的 `host_permissions` 已含 `<all_urls>`，换成任何 IP 都不需要改 `manifest.json`。

## 12. 停掉 WSL 旧实例（强烈建议）

两边都开着时，扩展只会往你填的那一个地址推，但同事可能还连着旧的；更麻烦的是你自己分不清数据在哪边。

```powershell
wsl -d Ubuntu-24.04 -- bash -c "cd '/mnt/c/Users/dataeye/AppData/Roaming/Trae CN/ModularData/ai-agent/work-mode-projects/6aac99a556e079edbea957d7/platform/deploy' && docker compose down"
```

再禁用开机自启：把启动文件夹里的 `dya-wsl-keepalive.vbs` 移到备份目录。

> `docker compose down` 不会删数据卷 `mysql-data`，WSL 里的历史数据仍留着可回退。确认虚拟机版稳定一周后再 `docker volume rm deploy_mysql-data`。

## 14. 日常运维

```bash
cd ~/dya/platform/deploy

docker compose ps                       # 状态
docker compose logs --tail 100 backend  # 后端日志
docker compose restart backend          # 只重启后端
docker compose down && docker compose up -d   # 全套重启
docker stats --no-stream                # CPU/内存
df -h /var/lib/docker                   # 磁盘（低于 10% 要清）
```

清镜像缓存（**确认没在构建时再跑**）：

```bash
docker image prune -f
docker builder prune -f
```

### 每日备份

```bash
cat > ~/backup-db.sh <<'EOF'
#!/bin/bash
set -e
cd ~/dya/platform/deploy
mkdir -p ~/backups
docker compose exec -T mysql mysqldump -uroot -p换成root密码 \
  --single-transaction --quick --databases collect_platform \
  | gzip > ~/backups/collect_platform-$(date +%F).sql.gz
find ~/backups -name '*.sql.gz' -mtime +7 -delete
EOF
chmod +x ~/backup-db.sh
```

```bash
( crontab -l 2>/dev/null; echo "0 3 * * * /home/dya/backup-db.sh >> /home/dya/backup.log 2>&1" ) | crontab -
```

恢复：`gunzip -c ~/backups/xxx.sql.gz | docker compose exec -T mysql mysql -uroot -p密码`

> 备份只存在虚拟机磁盘里，虚拟机坏了就一起没。每周手动 `scp dya@192.168.1.50:~/backups/*.sql.gz .` 拉一份到 Windows。

### 开机自启

`docker compose` 里每个服务都是 `restart: unless-stopped`，docker 服务本身 `enabled` 后，虚拟机开机自动拉起全部容器，**不需要像 WSL 那样挂保活脚本**。

## 15. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 装完系统没有 IP / ping 不通 | 桥接选错网卡，或公司网络限制 MAC | VirtualBox 设置 → 网络，改选实际联网那块；不行改 NAT + 端口转发（只能本机访问） |
| `netplan apply` 后 SSH 断 | 静态 IP 和网关/网段不一致 | 重进 VirtualBox 控制台改 `/etc/netplan/99-static.yaml`，`ip route` 对一遍 |
| `docker compose` 报 `请在 .env 设置` | `.env` 缺 `MYSQL_ROOT_PASSWORD` / `DB_PASSWORD` / `JWT_SECRET` | 补全第 8 步三个必填项 |
| 页面 502 | backend 刚起没就绪 | 等 20 秒；`docker compose logs backend` |
| 页面 200 但登录失败 | 迁移覆盖了用户表，密码不是 `admin123` | 用 WSL 版原来能登录的账号 |
| 同事打不开，你这台能开 | 虚拟机没桥接成功（拿到的是 NAT 私有 IP） | 虚拟机内 `ip -4 addr`，若为 `10.0.2.x` 就是 NAT，回第 1 步改桥接 |
| 扩展显示在线但数据不涨 | 扩展地址填的是 `127.0.0.1`，推到本机了 | 弹窗改平台地址，重载扩展 + F5 |
| 日志报「采集密钥无效」 | 弹窗密钥与后端 `collect.ingest-key` 不一致 | 都填 `dya-collect-2026` |
| 时间差 8 小时 | 时区 | compose 已固定 `TZ=Asia/Shanghai`，`docker compose exec backend date` 核对 |
| 磁盘满 | 镜像/构建缓存 | `docker image prune -f`，`df -h` 看是哪块满 |

## 16. 一次性命令汇总（照着从上到下粘）

```bash
# 1) 固定 IP（先改 enp0s3 / 192.168.1.50 / 192.168.1.1）
sudo tee /etc/netplan/99-static.yaml >/dev/null <<'EOF'
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [192.168.1.50/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [223.5.5.5, 119.29.29.29]
EOF
sudo chmod 600 /etc/netplan/99-static.yaml && sudo netplan apply

# 2) Docker
sudo apt update && sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker && sudo usermod -aG docker $USER
# 退出重登

# 3) 解包（先按第 7 步把 platform.tgz scp 到 ~）
mkdir -p ~/dya && tar -xzf ~/platform.tgz -C ~/dya

# 4) 配置（按第 8 步写好 .env）
cd ~/dya/platform/deploy && chmod 600 .env

# 5) 启动
docker compose build && docker compose up -d && docker compose ps

# 6) 迁移（按第 10 步，仅在需要保留历史数据时做）
```
