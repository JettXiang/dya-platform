## 1. 项目背景与目标

- 目标：从抖音挖掘「作者」——满足①视频挂载了合集、②视频上有「内容由 AI 生成」标识 的作者，采到他们的 `sec_uid`。
- 用途：`sec_uid` 经团队内部工具或扩展内置上传按钮入库（Redis），作为「AI 短剧/漫剧作者池」。
- 核心矛盾：作者池已接近饱和，新增越来越难；同时判定规则太宽会导致后台入库有效率低。所以核心诉求始终是「**精准优先、宁可少也不滥**」。

### 3.1 换装红线（升级前必读 —— 换目录会静默丢当日数据）

**实测结论（2026-10-28，v1.3.7 → v1.3.8 换装时确认）**：Chrome 里**移除**一个未打包扩展，会**连带删除该扩展的 `chrome.storage`**（LevelDB 整份清空），**哪怕 `key` 相同、扩展 ID 相同**。这不是扩展的缺陷，是 Chrome 的行为。 <!-- ver-ok -->

- **同目录覆盖 + 点「重载」→ storage 保住**（默认走这条）。
- **换目录（先「移除」再「加载已解压」）→ storage 整份没了**，面板里的「当日起点」、当日作者、设置项一起归零，且**没有任何提示**。

三步纪律：

1. **默认同目录覆盖**：把新版本文件覆盖进当前加载目录，然后到 `chrome://extensions` 点该卡片的「重新加载」。**不要**动加载列表里的条目。
2. **确需换目录**（例如目录名要跟着版本改）：先导一次 CSV 快照（面板「导出 CSV」= 当日全量），或按下面方式双备份；**并且必须先完全退出 Chrome**（任务管理器里不能有驻留的 chrome.exe，否则写 LevelDB 会被覆盖回旧值）：
   - 备份目录：`%LOCALAPPDATA%\Google\Chrome\User Data\Default\Local Extension Settings\<扩展ID>`（整目录复制）
   - 可选再加一份：面板「导出 CSV」+ 手动记下「当日起点」时刻
3. **回灌后必须校验四项**，缺一项不算成功：① `chrome://extensions` 卡片版本号 ② 扩展 ID（`mgcnblpoikblnppolddcjgaocnnalcbk`）③ 面板「本轮作者数」 ④ 面板「当日起点」时刻。

> 完整实测过程与截图见交付包 `07-实机冒烟-1.3.8/`（备份 8 文件 9,326,179 B → 回灌 → 2465/49068 起、还原后 2466/49069、起点 09:15:38、20 秒后 +3 作者 +86 视频）。

## 4. 硬性业务规则（务必遵守，不要破坏）

1. **采集口径（措辞已修正）**：只读取抖音页面自身发出的请求和文案，**不发额外网络请求、不生成签名**；但会**模拟页面交互**（换词、点「筛选/最新发布」、合成滚轮下滑、收割「相关搜索」DOM）。风控归因排查时统一按「不发额外请求，但会模拟点击/滚动」表述，不要再写成「纯被动、不主动」。
2. 只在「全部 / 二次元 / 小剧场 / 影视」四个栏目采集；误切到别的栏目自动停。
3. 频控：自动下滑间隔可选 4/6/8 秒（默认 4 秒），实际有抖动（多数 2.4~5.6 秒，约 15% 概率 12~24 秒长停顿）；换栏目滚满 40 次、换词滚满 30 次（或连续卡住 3 次）触发；换搜索词有 5 分钟全局冷却。
4. 触发人机验证 / 「搜索过于频繁」/ 强制登出 任一情况时，**立即停采集 + 停下滑 + 停自动换词/栏目**，只做非阻塞通知（页面浮层 + 系统通知），不用弹窗。
5. 连续无响应（约 90 秒无数据）不再静默停死：按 **30 秒 / 60 秒 / 2 分 / 5 分** 退避自动刷新并续采；用尽仍无响应才转人工。整页 502 则整页自动重新加载。
6. 所有持续运行的定时器回调入口要检查 `chrome.runtime.id` 有效性，失效即自清理（防「Extension context invalidated」刷屏）。
7. **一台电脑 = 一个账号 + 一个 Chrome 用户（profile）**，避免作者列表串号。
8. **随机刷新的开/停是全局粒度（已知限制）**：`refreshEnabled` / `refreshArmed` 存在共享 storage 里，拨一下所有采集页一起起表/停表，**做不到「A 页停、B 页继续」**（例如操作员临时在某一页人工核对时）。当前按「单采集页」使用，够用；多页并行时需注意这个限制。

## 5. 采集判定逻辑（两条件拦截 + 类型分级在后端）

采集时的拦截条件只有两条：

1. 挂载合集（`requireMix`，面板可取消勾选放宽）
2. 有「内容由 AI 生成」声明（`requireAi`，面板可取消勾选放宽）

第 3 条「内容类型」**不在采集时拦截**（`VALID_FILTER_ENABLED = false`，导出全量），它是搜索词的锚定规则 + 后端分级复核口径：

**白名单**（合集名 + 昵称 归一化后，命中任一即通过；已删掉光杆「AI」，避免放过「AI说唱/AI音乐」这类）：

```
漫剧, 短剧, AIGC, 动漫, 动画, 次元, 穿越, 重生, 逆袭, 赘婿, 战神, 系统,
王妃, 豪门, 漫画, 番剧, 小剧场, 剧场, 剧集, 末世, 自制动画
```

**黑名单**（命中任一即排除）：

```
汪汪队, 立大功, 民间故事, 寓言, 动物世界, 怀旧, 童年, 军旅, 科普, 双语, 跟读,
后室, 未解之谜, 领养, 咕嘎, 人生副本, 阅读, 育儿, 儿童, 宝宝, 儿歌, 纪录片,
解说, 混剪, 搬运, 影视解说
```

> 经验：新增搜索词必须锚定白名单词、避开黑名单词；否则捞回来的作者在后端复核里大概率判无效，属无效投入。

**当前版本的实际行为**：导出为全量（`VALID_FILTER_ENABLED = false`），有效性分级复核挪到监控后台做（规则判断 + 人工复核）。后台里另有「视频数阈值 = 2」这张可选网。
