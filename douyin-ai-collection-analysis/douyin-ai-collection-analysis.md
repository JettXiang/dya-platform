# 抖音 AI 合集作者采集：问题分析与增量提升方案

> 内部数据分析 · 版本 v1.0 · 2026-09-18

## 摘要

采集增量的瓶颈不是"没有作者可挖"，而是推荐 feed 收敛导致的曝光枯竭，叠加 Redis 存量已达 8 万带来的撞库损耗。数据显示新增量随"换栏目/换关键词"严格递增（11→33→134→226），证明"换路"是唯一有效杠杆；而固定的 2.78s 滑动节奏和后台挂机方式，则是触发"服务异常"风控的直接原因。

---

## 一、背景与现状

采集工具是一个 Chrome 插件，在抖音 **推荐 / 精选 / 搜索** 页面收集同时满足两个条件作者身份的 `sec_uid`：

1. 视频挂载了合集
2. 带"内容由AI生成"声明

插件**只被动读取浏览器里抖音页面自身发出的 feed 请求和页面文案，不另打签名、不主动发请求、不上传数据到别处**。

- **产出链路**：插件导出 sec_uid（TXT/CSV/JSON）→ 上传工具去重 → 写入国内 Redis（key `douyin_topic_search_sec_id`）。
- **当前规模**：Redis 集合总数已到 **80,579** 个 sec_uid，处于"高位撞库"阶段。
- **核心痛点**：单次新增量过低（最低个位数），目标是单次新增过百、越多越好。

---

## 二、核心结论（先行）

两个问题可以一句话概括：

> **增量枯竭是因为 feed 收敛 + 高位撞库，解决办法是"换路"；"服务异常"是因为固定匀速 + 后台挂机，解决办法是"降频随机化 + 自动复位"。**

关键数字：

| 指标 | 数值 | 说明 |
|---|---|---|
| 新增量随"换路"递增 | 11 → 226 | 挂后台 11 → 换栏目 134 → 多栏目 226 |
| 昨日新增率 | 5.4% | 226 新增 / 4167 有效，其余 94.6% 撞库 |
| Redis 存量 | 80,579 | 池子越大，撞库越严重 |
| 滑动间隔 | 2.78s | 固定匀速，触发风控的机械特征 |

---

## 三、问题一：挂后台出现"服务异常，请重新刷新拉取"

### 定位

插件是被动读取、不主动发请求，所以这个报错**不是脚本触发的风控**，而是抖音前端那一次 feed 请求自己失败后弹的通用错误框。要解决的是"让抖音前端请求别失败"，而不是修采集逻辑。

### 根因一：固定 2.78s 匀速高频 → 触发风控

实测滑动间隔基本固定在 2.78~2.80s，只有约 0.02s 抖动。这种匀速、无停顿、机械化的请求节奏，是风控识别机器的典型特征。抖音在持续高频下会打标，后续 feed 请求返回非 0 错误码，前端就弹"服务异常"，只能刷新重拿 token 才能恢复。

### 根因二：后台节流 + token 过期 → 请求直接失败

标签页切到后台后，浏览器会大幅节流定时器，长轮询/网络套接字可能被断开；同时 feed 依赖的 `msToken`、`ttwid`、`sessionid`、设备指纹等会过期。后台挂 30~60 分钟不刷新，token 自然失效，下一次加载就失败。

### 解决办法

- **降频随机化**：滑动间隔从固定 2.78s 改成 2~6s 随机，并加入偶发长停顿（8~15s 模拟"看视频"）。
- **自动复位**：在插件里监听"服务异常"文案，出现即自动 reload，不用人工刷。
- **定期主动刷新**：每 15~20 分钟主动刷新一次页面换新 token，避免挂到过期。
- **别纯后台挂机**：要么保持前台窗口，要么用独立窗口/profile 轮换；后台节流本身就会破坏采集节奏。

## 四、问题二：单次新增量过低

### 证据链

四批数据的完整证据链如下（新增率 = 本次新增 ÷ 文件有效数）：

| 采集方式 | 文件有效数 | 本次新增 | 新增率 | Redis 总数 |
|---|---:|---:|---:|---:|
| 挂后台不动（更早） | 2,197 | 11 | 0.5% | 72,346 |
| 挂后台不动（大前天，09-16） | 3,405 | 33 | 0.97% | 76,221 |
| 换几个栏目（第二天） | 3,413 | 134 | 3.9% | 76,514 |
| 多次换栏目（昨天） | 4,167 | 226 | 5.4% | 80,579 |

**这条链条直接证明：新增量与"换栏目次数"严格正相关，与"挂机时长"无关。**

挂后台不动，哪怕挂着，新增也只有 11~33 条；一旦开始换栏目，立刻跳到 134、226。这不是"作者被采完了"，而是**同一路 feed 刷穿了之后不再产生新曝光**。

### 隐藏信号：新增率天花板只有 5.4%

即便昨天换了多次栏目，采到 4,167 个作者，也只有 226 个是新的——**94.6% 都撞进了已有的 8 万存量里**。这说明两个关键事实：

1. **精选页的"栏目"是有限的几个频道**，它们的作者池和存量高度重叠。换栏目现在好使是因为踩到了之前没踩过的频道；栏目踩完一轮就会再次收敛。
2. 随着 Redis 持续增长（已经 8 万），撞库只会越来越严重，**"换栏目"是当前有效但会边际递减的有限手段**。

另外，抖音推荐本身**按账号（+设备）做个性化**，刷得越久算法越把你往画像里圈，单账号存在天然天花板，这也是单账号做到后面越来越难的原因之一。

## 五、接下来怎么试

下面这些是**尝试方向**，先手动试、看数据，跑得通再说下一步，不急着做决定。核心思路就一条：**别在同一个 feed 里死刷，多换路去采新的池子。**

### 1 · 多关键词搜索

- **怎么试**：不再只搜"漫剧"，每个时段换一批关键词——短剧 / AI短剧 / 动漫解说 / 民间故事 / 历史故事 / 情感故事 / AI音乐 / 虚拟人 等，每个词搜一阵、能采多少采多少再换下一个。
- **为什么**：每个关键词是一批独立作者，不跟已有 8 万存量撞车，直接绕开 feed 收敛。
- **预期**：新增率有望突破现在的 5.4%，是当前最值得先试的一条。

### 2 · 顺着作者找相似作者

- **怎么试**：命中一个 AI 作者后，点进主页翻相似作者 / 相关合集 / 相关推荐，沿着这条线继续采。
- **为什么**：AI 作者常成簇出现（同类题材、同类工作室），一个作者往往能带出一串。
- **预期**：单点放大成批量，是搜索之外的第二条路子。

### 3 · 先放宽判定，捞完再清洗

- **怎么试**：插件的两个勾选框先只勾"内容由AI生成"，把"必须挂载合集"关掉，全量采一段，导出后再用清洗工具二次过滤。
- **为什么**：现在双条件都要满足，能命中的本来就少；先放宽多捞一层候选，再在清洗端筛回想要的。
- **预期**：曝光基数立刻变大，值得先跑一轮看效果。

### 4 · 换栏目（已经在做，继续做）

- **怎么试**：精选页顶部栏目轮流切，不长期死磕一个；结合上面的关键词搜索一起换。
- **为什么**：数据已证明换栏目有用（134→226），但它有上限，只能当常规手段。
- **预期**：稳定但封顶，配合前两条一起用效果更好。

### 5 · 滑动节奏调慢点、随机点

- **怎么试**：滑动间隔从固定 2.78s 手动往 2~6s 拉开、偶尔停 8~15s；看到"服务异常"就手动刷新一下。
- **为什么**：太快太匀速容易被风控，慢一点、模拟人一点，报错会明显变少。
- **注意**：这处要动插件源码，**暂时先不改代码**，用人工控制节奏验证就够。
